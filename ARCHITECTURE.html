ARCHITECTURE — The Foresight Investor System

READING CONTRACT — mandatory before any research or modification.
Every builder (human or AI) must read, in order: hotcache.md → this file → AGENTS.md (schema
& guardrails) → CADENCE.md (staleness contract) → the specific module docs below. Every session
that studies or changes the system must append a dated entry to SYSTEM-RESEARCH-LOG.md —
that log is how future builders review what was learned and feed back into the mechanics.
Decisions produced by this system are for the operator's own book only — never advice to others.

1. What this system is

A personal global multi-asset research + allocation platform built as an Obsidian wiki
(the vault) driven by a Python quant engine (the scripts). It ingests market/economic/analyst
data from keyless public sources, computes independent factor ratings (FFM) and strategy
sleeves, runs backtests and tournaments, produces rule-based capped allocations, and publishes
everything to three interactive HTML surfaces + a rendered public website. One operator;
AI agents do the writing, filing, and bookkeeping per AGENTS.md.

Numbers at a glance (2026-09-26): 35 themes · 8 meta-forces · 347 instruments ·
~87 MB cached history (5y + 10y prices) · 438 wiki pages · 4 auto-refreshed HTML surfaces (3 public + 1 private) ·
~46 Python modules · 13-command CLI (foresight). There is also a 🔒 PRIVATE portfolio layer (the operator's
actual book) — see §6a; it never deploys publicly.

4. Engine layer — what computes what

Engine Input → Output Consumed by
FFM (ffm_signals → ffm_score) signals + fundamentals → 6 factor grades (Momentum/Value/Quality/Growth/CMA/Revisions, A+→F) → composite rating (Strong Buy…Strong Sell) with regime-dependent weights. Non-equity (fx/commodity/crypto/cash) = momentum-only, honestly labeled workbench Universe/Security tabs, research notes, consensus
Sleeves (signals.py) signals.parquet → 6 cross-sectional sleeves: momentum, value, quality, macro_rotation, contrarian (value+52w-off, gated by revisions), longterm (quality+drawdown+inv-vol) allocator, backtest, workbench
MDAEM v4 (mdaem_v4.py) quant dims 3/5/6/7/9 + composite per candidate (operator completes 5 qualitative dims + 10 gates) sourcing pipeline, DECIDE op
Allocator (alloc/) sleeves+FFM+meta → capped portfolios (3 risk profiles × 6 lenses). Caps: name 5–10%, theme 8–15%, AI-cluster 20–30%, region 30–50%, cash floor. High-cash is the honest output when caps bind workbench Allocator tab, book memos
Backtest (backtest.py) walk-forward, top-20/sleeve monthly rebalance quarterly REVIEW
QAE (qae.py) 14 price/volume factors → rank-IC (Newey-West) → IR-weighted composite → inverse-vol book (10% vol target) quant-desk, ALPHA op (monthly)
Tournament (tournament.py) every registered strategy, same days/costs, split-sample gate quarterly
recommend / monitor sleeves+FFM → top-N adds (T1/MED tiers); price/volume alerts continuous-research, Research tab
ffm_vs_sa FFM × SA ratings → agreement/disagreement table (external calibration) Sources tab

5. Decision & accountability chain (the vault layer)

Every call is falsifiable and dated: signal-monitor (sensor thresholds) → decision-register
(sized ADD/TRIM/HOLD/EXIT) → prediction-ledger (P-calls with resolve-by) → track-record
(scored outcomes). Book memos (wiki/syntheses/book-rec-*.md, qae-book-*.md) are the operator-facing
output — own-book only. Full protocol in AGENTS.md §10 (MONITOR/SCAN/DECIDE/REFRESH/SOURCE/BACKTEST/
BUBBLE-WATCH/ALPHA/TOURNAMENT operations).

6a. 🔒 The private portfolio layer (added 2026-09-26 — LOCAL-ONLY)

The public engine tracks the model book; the private layer tracks the operator's actual cross-account book.
Pipeline: statements/PDFs/screenshots → scripts/_portfolio/holdings.json (hand-maintained ledger, per-row
provenance) → optional scripts/_portfolio/lookthrough.json (ETF/fund top-holdings, live-sourced) →
scripts/portfolio.py (2-level asset taxonomy, look-through aggregation, HHI, blueprint caps, dual net-worth
stress incl. real estate, FX look-through) → scripts/_portfolio/_portfolio_data.js →
portfolio-dashboard.html (7 tabs; served from :8765). Privacy gates: private-* markdown prefix is
excluded from build_web.py rendering AND flagged by deploy_web.sh leak scans (public portfolio-blueprint
unaffected); raw statements live under raw/statements/ (raw/ is never deployed).
Hub pages: private-portfolio-register · private-portfolio-x-ray-2026-09-26.
Discipline: unknown figures stay null/UNAVAILABLE (never guessed); every figure traces to a statement or a
cited live source; UNAVAILABLE funds are listed explicitly on the dashboard.

8. Quality control & sustainability (non-negotiable)

  1. Provenance on every figure (_provenance.csv); UNAVAILABLE beats fabricated — always.
  2. Asset-class honesty: non-equity gets momentum-only, never fake value/quality grades.
  3. Cross-validation: FFM vs SA disagreement table; engine vs market in track-record.
  4. Deploy pre-flight (deploy_web.sh): zero source markdown, zero confidential files
    (scenario-hrm-competition.md hard-excluded), zero key/token patterns, isolated push repo.
  5. Vault lint (AGENTS §5 LINT): frontmatter, links resolve, orphans, wanted pages,
    stale claims — run after any mass edit (last full pass 2026-09-26: 435 pages, 0 orphans).
  6. Staleness visibility: hotcache.md dates + CADENCE contract + last_scan frontmatter.
    Data older than 10 trading days = flag, don't silently use.
  7. Generator hygiene: auto-pages are regenerated wholesale — hand-edits to generated pages
    are lost by design; put durable insight in the page's non-generated sections or a synthesis.
  8. Point-in-time integrity (added 2026-10-03): every refresh archives the full engine
    state to scripts/_hist/archive/<date>/ + appends recommendation-journal.jsonl
    (scripts/snapshot_archive.py, wired into weekly_refresh) — post-mortems read the archive,
    never git archaeology. Living hub pages get a dated Changelog bullet on conviction changes.
  9. Raw/ is immutable. raw/assets/ is the home for source images. Never edit history in
    _hist/ — append/refresh, never rewrite.

9. Change protocol — touch X, update Y

If you change… You must also…
instrument_universe.py (add/remove ticker) run refresh_instruments + fetch_history --inc + signals + ffm_signals + ffm_score + build_workbench + inject; research notes --all; commit
A factor/weight in FFM re-run ffm_signals + ffm_score; note the change in log.md; expect rating distribution shifts (compare before/after)
Allocator caps/profiles re-run optimizer for all 3 risks; update [portfolio-blueprint](portfolio-blueprint.html) + book memos
A workbench tab's JS QC in browser (local 8765) before deploy: page boot, tab render, data as-of, console clean
build_web.py copy list verify every runtime-fetched asset serves 200 on the public site after deploy
Schema/guardrails sync AGENTS.md ↔ CLAUDE.md (keep identical except self-reference line)
Any mass wiki edit run the link-graph audit (lint) + append to SYSTEM-RESEARCH-LOG.md
Run any refresh chain run scripts/snapshot_archive.py after it (or rely on weekly_refresh 3f)

10. Extension recipes

  • Add an instrument: append to the right theme in instrument_universe.py ((ticker, note)),
    non-US needs an INSTRUMENT_META entry (region/currency/exchange), then the refresh chain (§9 row 1).
  • Add a theme: new block in UNIVERSE (slug+meta+etfs+names), create wiki/concepts/<slug>.md
    per the analyst-grade template (AGENTS §10), add to trend-radar, run tables.
  • Add a sensor/event-watch chip: row in build_event_watch() (build_workbench.py) —
    reading from _snapshot.json keys only; no snapshot key = no chip (never hardcode a value).
  • Add a strategy idea: register it in tournament.py as new (never edit a loser into a
    winner); it counts in the deflation N forever.
